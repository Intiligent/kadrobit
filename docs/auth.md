# Авторизация

Эпик: [KB-1](https://github.com/Intiligent/kadrobit/issues/1). Документ дополняется по мере выполнения этапов.

## Схема

- Вход в приложение — обычная сессия Laravel (guard `web`).
- Для `/api/*` — guard `api` (драйвер `passport`). Токен — personal access token Passport, живёт столько же, сколько сессия.
- Токен для API выдаётся при входе и передаётся в HttpOnly cookie `api_token` (подробнее — «Вход, регистрация, токен в cookie»).
- Расширение браузера входит через OAuth с PKCE и получает токены со скоупом `extension`, которые открывают только его API ([browser-extension.md](browser-extension.md#вход-расширения)).

## Вход, регистрация, токен в cookie

Задача [KB-4](https://github.com/Intiligent/kadrobit/issues/4).

### Маршруты

| Метод | Путь | Middleware | Что делает |
|---|---|---|---|
| GET | `/login` | guest | Страница входа. `?redirect=/путь` — куда вернуть после входа (только пути этого сайта) |
| POST | `/login` | guest | Вход. После 5 неудачных попыток для пары email + IP вход блокируется на минуту, ошибка показывается в поле email |
| GET | `/register` | guest | Страница регистрации |
| POST | `/register` | guest, `throttle:auth-forms` | Регистрация, сразу вход |
| POST | `/logout` | auth | Выход. Только POST |
| POST | `/auth/token` | auth, `throttle:api-token` | Новый токен в cookie для текущей сессии (вызывает API-клиент после 401) |

- Гостя со страниц под `auth` отправляет на `/login`, вошедшего со страниц под `guest` — на `/`.
- Email и username хранятся в нижнем регистре (мутаторы модели `User`, при любом способе создания), вход принимает email в любом регистре.
- Username: латиница, цифры, `.`, `_`, `-`, от 3 до 20 символов. Пароль — от 8 символов.
- Лимиты: `auth-forms` — 6 запросов в минуту на каждую форму и IP отдельно (регистрация, запрос ссылки, сброс); `api-token` — 30 в минуту на пользователя (`AppServiceProvider`). Обычный `throttle:6,1` для гостя считает только по IP, и все такие маршруты делили бы один счётчик.
- Inertia-форма (POST/PUT/PATCH/DELETE), упёршаяся в лимит запросов (429), возвращает назад с flash-сообщением вместо страницы 429. GET-переходы так не обрабатываются: возврат назад мог бы попасть на ту же страницу и зациклиться.

### Токен в cookie

- На каждый вход (событие `Login` guard `web`, в том числе «запомнить меня») `LoginListener` создаёт personal access token и ставит cookie `api_token`: HttpOnly, SameSite не слабее `lax`. Вход без HTTP-сессии (artisan, очередь, сидер) токен не выдаёт.
- **Токен живёт столько же, сколько сессия** (`SESSION_LIFETIME`, по умолчанию 120 минут), cookie — так же. Пока пользователь активен, токен продлевается; если вкладку просто закрыли, API-доступ пропадает вместе с сессией.
- Cookie не шифруется (`encryptCookies except`): токен — подписанный JWT. `Passport::cookie()` не используется: это имя механизма Passport с зашифрованной cookie, с нашей оно бы конфликтовало.
- В сессии хранятся id токена, его хеш и время истечения, поэтому проверка «в cookie токен этой сессии и он не истекает» не обращается к базе.
- `PassportCookieAuthentication` (группа `api`) превращает cookie в `Authorization: Bearer`, если заголовка нет. Для POST/PUT/PATCH/DELETE — только если есть `X-Requested-With: XMLHttpRequest` (`api.js` отправляет его всегда). SameSite разделяет сайты, но не поддомены одного домена: обычная форма с чужого поддомена такой заголовок поставить не может, а fetch с другого источника остановит CORS.
- `RenewApiToken` (группа `web`) выдаёт новый токен, если у вошедшего пользователя нет cookie, в cookie чужой или устаревший токен, или до истечения меньше 5 минут. Старый токен сессии отзывается.
  - Продление сессии занимает её на 10 секунд (`Cache::add`), параллельные запросы токен не выпускают: иначе каждый выпустил бы свой, и при выходе отозвался бы только один.
  - Не срабатывает на `/logout` и `/auth/token` и если токен в этом запросе уже выдан (например, при входе через «запомнить меня»).
- Если API ответил 401, а сессия жива (токен отозван или истёк), `api.js` вызывает `POST /auth/token` и повторяет запрос. Если сессии нет — показывает диалог входа.
- `LogoutListener` отзывает только токен текущей сессии и удаляет cookie: на других устройствах вход сохраняется.
- Отозванные и истёкшие токены удаляет `passport:purge` раз в сутки (`routes/console.php`); на сервере должен работать `php artisan schedule:run`.

## Сброс пароля

Задача [KB-5](https://github.com/Intiligent/kadrobit/issues/5).

| Метод | Путь | Middleware | Что делает |
|---|---|---|---|
| GET | `/forgot-password` | guest | Форма запроса ссылки |
| POST | `/forgot-password` | guest, `throttle:auth-forms` | Отправляет письмо со ссылкой |
| GET | `/reset-password/{token}?email=…` | — | Форма нового пароля (ссылка из письма). Открыта и вошедшим: ссылку могут открыть в браузере, где уже есть вход |
| POST | `/reset-password` | `throttle:auth-forms` | Меняет пароль, завершает текущую сессию, если она есть, и ведёт на `/login` с сообщением |

- **Ответ не раскрывает, есть ли аккаунт:** на любой email форма отвечает одинаково («если аккаунт есть, письмо отправлено»), в том числе при повторном запросе в течение минуты (брокер отправляет не чаще раза в минуту). Неверный токен, истёкший токен и неизвестный email на странице сброса дают одну и ту же ошибку «ссылка недействительна».
- **Ссылка живёт 60 минут** и одноразовая (`config/auth.php` → `passwords.users.expire`).
- **Письмо** — `ResetPasswordNotification`, через очередь: форма отвечает одинаково быстро, есть аккаунт или нет. Шаблон — `resources/views/emails/reset-password.blade.php` на общем `emails/layout.blade.php`.
- **После сброса** тот, кто знал старый пароль, теряет доступ на всех устройствах при любом драйвере сессий:
  - новый `remember_token` завершает входы «запомнить меня»;
  - `AuthenticateSession` (группа `web`) хранит в сессии хеш пароля и при следующем запросе завершает каждую сессию, где пароль сменился; `LogoutListener` отзывает токен этой сессии;
  - `PasswordResetListener` сразу отзывает токены веб-сессий (`name = web`), чтобы API перестал отвечать ещё до следующего запроса страницы. Токены других видов (например, для интеграций) — отдельные ключи, их сброс пароля не трогает.
- Пароль — не короче 8 символов, с подтверждением.

## Подтверждение email

Задача [KB-6](https://github.com/Intiligent/kadrobit/issues/6).

Мягкий барьер: сайт открыт неподтверждённому пользователю, в шапке — баннер «Confirm now». Только маршруты с middleware `verified` отправляют его на `/verify-email` (стандартный `EnsureEmailIsVerified` ведёт на `verification.notice`).

| Метод | Путь | Middleware | Что делает |
|---|---|---|---|
| GET | `/verify-email` | auth | Экран ввода кода (`verification.notice`) |
| POST | `/verify-email` | auth, `throttle:verify-email` | Проверка кода |
| POST | `/verify-email/resend` | auth, `throttle:verify-email-send` | Новый код |
| PUT | `/verify-email/email` | auth, `throttle:verify-email-send` | Смена email, пока он не подтверждён, и новый код |
| GET | `/verify-email/{id}/{hash}?code=…` | `signed`, `throttle:verify-email-link` | Ссылка из письма; работает и без входа |

- **После регистрации** событие `Registered` отправляет код (`User::sendEmailVerificationNotification()` → `EmailVerificationService::issue()`), пользователь попадает на экран ввода кода.
- **Код:** 6 цифр, живёт 15 минут, 5 попыток. У пользователя один живой код: новый удаляет старый. Код привязан к адресу, на который отправлен, — после смены email старый код не работает.
- **Хранение:** в `email_verification_codes` лежит только HMAC-SHA256 кода с ключом приложения. Без `APP_KEY` утёкшую таблицу не перебрать.
- **Попытки** засчитываются атомарно до сравнения кода: параллельные запросы не проскочат лимит.
- **Повторная отправка:** не чаще раза в 60 секунд и не больше 10 писем в сутки на пользователя. Смена email на новый адрес не ждёт 60 секунд, но входит в суточный лимит. Отправка идёт под блокировкой на пользователя (`withSendLock`): параллельные запросы из двух вкладок не отправят два письма.
- **Ссылка в письме:** подписанная (`URL::temporarySignedRoute`), в ней id кода из того же письма, и работает она, пока жив этот код: после повторной отправки, смены адреса или исчерпания попыток ссылка из старого письма показывает ошибку. `hash` — `sha1` адреса, поэтому ссылка на прежний адрес не сработает. У ссылки свой лимит `verify-email-link`, неверные коды в том же браузере его не расходуют. Подпись доказывает владение адресом, поэтому вход не нужен: открытая на телефоне, ссылка подтверждает email и ведёт на страницу входа; в той же сессии — возвращает на исходную страницу.
- **Письмо** — `VerifyEmailNotification`, через очередь и **зашифровано** в ней (`ShouldBeEncrypted`): пока письмо не отправлено, код лежит в задаче. Перед отправкой `shouldSend()` проверяет, что код ещё жив и выдан на текущий адрес: письмо, ждавшее в очереди во время смены email или повторной отправки, не уходит. Код стоит и в теме письма, чтобы его было видно в списке писем.
- **Смена email:** ошибка «адрес занят» сформулирована нейтрально, чтобы форма не подсказывала, какие адреса зарегистрированы.
- Истёкшие коды удаляет `model:prune` раз в сутки (`routes/console.php`).
- **Подтверждение** (`markVerified()`) — атомарный `UPDATE … WHERE email_verified_at IS NULL`: код и ссылка, использованные одновременно, отправят событие `Verified` один раз.
- `markVerified()` использует и вход через Google: там адрес подтверждает сам Google.

## Вход через Google

`laravel/socialite`, драйвер `google`, stateful (state OAuth хранится в сессии, intended URL переживает поход в Google).

| Метод | Путь | Middleware | Что делает |
|---|---|---|---|
| GET | `/oauth/google/redirect` | guest | Уводит на экран согласия Google |
| GET | `/oauth/google/callback` | guest | Возврат из Google: вход или создание аккаунта |

- **Включение:** кнопка «Continue with Google» на страницах входа и регистрации и оба маршрута работают, только когда заданы `GOOGLE_CLIENT_ID` и `GOOGLE_CLIENT_SECRET` (`OAuthController::googleEnabled()`, проп `googleEnabled`). Без них маршруты отвечают 404, кнопки нет.
- **Redirect URI:** `GOOGLE_REDIRECT` по умолчанию `/oauth/google/callback`. Путь Socialite достраивает от текущего хоста, поэтому одно значение подходит и локально, и в продакшене. В Google Cloud нужно прописать полные адреса для каждого хоста.
- **Сопоставление аккаунтов** — по email (`GoogleAccountResolver`):

| Аккаунт с этим email | Google подтвердил email (`email_verified`) | Результат |
|---|---|---|
| нет | да | Создаём (имя, фамилия, `username` из email, аватар), сразу подтверждён, вход |
| нет | нет | Создаём, код подтверждения как при обычной регистрации, вход и экран ввода кода |
| есть, подтверждён | да | Вход, данные аккаунта не меняются |
| есть, не подтверждён | да | Подтверждаем, **меняем пароль и remember token**, отзываем токены (`PasswordReset`), вход |
| есть | нет | Отказ: «войдите по паролю» |

- **Почему меняется пароль:** неподтверждённый аккаунт мог заранее зарегистрировать кто-то другой на чужой адрес и ждать, пока владелец войдёт через Google. Google доказывает владельца, поэтому тот, кто задал пароль, теряет доступ: `AuthenticateSession` завершает его сессии, `PasswordResetListener` отзывает API-токены.
- **Отказ без подтверждения:** иначе любой, кто добавит чужой адрес в Google-аккаунт без подтверждения, получил бы чужой аккаунт.
- **Пароль нового аккаунта** — случайный, его никто не знает. Войти по паролю можно, задав его через «Forgot password?».
- **Ошибки:** отказ на экране согласия (`?error=…`), устаревший state и сбой связи с Google возвращают на `/login` с flash-сообщением; сбой пишется в лог.

### Что нужно сделать владельцу

1. В [Google Cloud Console](https://console.cloud.google.com/) создать проект (или взять существующий).
2. **APIs & Services → OAuth consent screen:** тип External, название приложения, email поддержки, логотип и домен `kadrobit.net`; scopes `openid`, `email`, `profile`. Опубликовать приложение (In production), иначе войти смогут только тестовые пользователи.
3. **Credentials → Create credentials → OAuth client ID**, тип Web application. Authorized redirect URIs:
   - `https://kadrobit.net/oauth/google/callback`;
   - локальный адрес, например `http://kadrobit.loc/oauth/google/callback`.
4. Client ID и Client secret прописать в `.env`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
