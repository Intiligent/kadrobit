# Стоки: статус подключения

Обновлено 30.10.2026. Документ обновляется с каждой задачей, которая меняет поддержку стока: новая доставка, метаданные, категории, проверка на настоящем аккаунте.

Общая механика публикации — [`docs/publishing.md`](../publishing.md), исследование способов загрузки — [«Фотостоки: API для загрузки фото с метаданными»](../Фотостоки%20API%20для%20загрузки%20фото%20с%20метаданными.md), справочник — `database/seeders/MarketplaceSeeder.php`.

## Как считается покрытие

Пять этапов по 20 %. Отправка на модерацию (submit) в процент не входит: публичного API для неё нет ни у одного стока, автор нажимает Submit на сайте (см. «Отправка на модерацию»).

| Этап | Готово, когда |
| --- | --- |
| 1. Справочник | Сток есть в `MarketplaceSeeder`: протокол, сервер, правила файлов (`file_rules`) и текста (`metadata_rules`). Без правил файлов — частично, 10 % |
| 2. Подключение | Вход проверяется в настройках (`ConnectionTester`) |
| 3. Файлы | Есть доставка в `config/publishing.php` (`deliveries`): работы уходят из очереди на сток |
| 4. Текст и ключевые слова | Название, описание и ключевые слова доходят до стока без ручного ввода: IPTC/XMP в файле или CSV |
| 5. Категории | Категории в `MarketplaceCategorySeeder` и доходят до стока. У стока без категорий этап засчитывается вместе с этапом 4 |

«Максимум» — сколько можно автоматизировать известными сегодня способами.

Статусы:
- ✅ **Работает** — всё автоматизируемое сделано и проверено.
- 🟡 **Частично** — работы уходят, но часть метаданных автор вводит на сайте.
- 🔵 **Только подключение** — аккаунт подключается и вход проверяется, но в публикации сток пропускает работы как «не поддерживается» (нет доставки).
- ⚫ **Нельзя автоматизировать** — у стока нет FTP и API; в настройках выключен (`is_active = false`), остаётся ручная загрузка — пакет для неё в [KB-34](https://github.com/Intiligent/kadrobit/issues/34).

## Что уже можно подключить

- **Пользуемся:** Dreamstime и Shutterstock — работы отправляются из Kadrobit. На Shutterstock после отправки остаётся выбрать категории на сайте.
- **Отправка готова, ждёт проверки на аккаунте:** Alamy — фото и векторы EPS ([KB-74](https://github.com/Intiligent/kadrobit/issues/74)).
- **Можно подключить аккаунт, но работы не уйдут:** Adobe Stock, Vecteezy, 123RF, Magnific, Pond5, Depositphotos. Вход проверяется, доставка — [KB-33](https://github.com/Intiligent/kadrobit/issues/33).

Предлагаемый порядок для KB-33, от простого к сложному:

1. **Vecteezy** — CSV по FTP, как у Dreamstime: можно сразу довести до 100 %. Нужен адрес FTP-сервера.
2. **123RF** и **Magnific** — IPTC в JPEG, как у Shutterstock; надо выяснить, есть ли категории.
3. **Adobe Stock** — SFTP есть не у всех аккаунтов, CSV грузится только через сайт: категории и CSV — тем же способом из браузера, что и в KB-54.
4. **Pond5** — только файлы: метаданные вводятся вручную. Alamy сделан в KB-74: IPTC он читает.
5. **Depositphotos** — сначала изучить сервер и метаданные.

## Отправка на модерацию

У всех стоков Submit делается на сайте, публичного API нет. Автоматизировать можно только из браузера автора, где он уже вошёл на сток (как задумано для Shutterstock в KB-54); с сервера — нельзя, это потребовало бы хранить вход автора в веб-кабинет.

| Сток | Куда попадают файлы | Что остаётся автору |
| --- | --- | --- |
| Dreamstime | Unfinished | Одна кнопка «Submit N files» на все заполненные работы |
| Shutterstock | To submit (Не отправлено) | Выбрать категории и отправить |
| Alamy | Сразу в очередь QC: загрузка и есть отправка | Ничего; описание и уточнения — в Image Manager |
