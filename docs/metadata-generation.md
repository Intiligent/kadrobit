# Генерация метаданных

Задачи: эпик [KB-35](https://github.com/Intiligent/kadrobit/issues/35), выбор модели — [KB-37](https://github.com/Intiligent/kadrobit/issues/37), генерация для работ — [KB-38](https://github.com/Intiligent/kadrobit/issues/38).

По превью работы модель пишет заголовок, описание, ключевые слова и выбирает категории маркетплейсов. Провайдер переключается в конфиге: остальной код знает только интерфейс.

## Устройство

| Класс | Что делает |
|---|---|
| `Services\Metadata\Contracts\MetadataGenerator` | Интерфейс провайдера: `generate(GenerationRequest): GenerationResult`, `name()` — «провайдер:модель» |
| `Services\Metadata\Drivers\OpenAiMetadataGenerator` | OpenAI Responses API: инструкции, текст контекста и картинка (data URL), строгая JSON-схема, `store: false`. На 429 и 5xx — ещё две попытки с растущей паузой, остальные ошибки сразу |
| `Services\Metadata\MetadataGeneratorFactory` | Создаёт генератор по имени драйвера из `config/metadata.php`; `make(overrides: ['model' => …])` — для сравнений |
| `Services\Metadata\MetadataPrompt` | Общие для всех провайдеров инструкции, контекст работы и схема ответа |
| `Services\Metadata\MetadataSanitizer` | Приводит ответ к лимитам и записывает каждое исправление в `fixes` |
| `Services\Metadata\ImagePreparer` | JPEG из превью, не больше `metadata.image_size` (1024 px) по длинной стороне; прозрачность заливается белым, CMYK переводится в sRGB |
| `GenerationRequest` / `GenerationResult` / `TokenUsage` | Вход (картинка, тип, имя файла, дата, место, категории), результат, токены и стоимость. `GenerationRequest::categoryLists()` — списки категорий маркетплейсов для типа работы, общие для генерации и сравнения |

В контейнере `MetadataGenerator` — провайдер из `METADATA_DRIVER`.

**Новый провайдер:** класс, реализующий `MetadataGenerator` (получает `MetadataPrompt` и `MetadataSanitizer`, сам только ходит в API), ветка в `match` в `MetadataGeneratorFactory`, блок в `metadata.drivers` и цены моделей в `metadata.prices`.

### Промпт и ответ

- **Инструкции** (`instructions`) стоят первыми и меняются только со списками категорий — провайдеры кешируют такой префикс. Контекст работы (тип, имя файла, дата и место из EXIF) идёт отдельным сообщением вместе с картинкой.
- **Схема** — строгое подмножество JSON Schema, которое принимают OpenAI, Anthropic и Gemini: все поля обязательны, лишних нет, категории — `enum` из списков маркетплейсов. Длины и количества схемой не задать, их проверяет `MetadataSanitizer`.
- **Лимиты** (`metadata.limits`): title ≤ 70 символов без запятых, description ≤ 150 — одно предложение, до 49 ключевых слов. Это самые строгие значения среди маркетплейсов: Adobe Stock (title до 70 в CSV, до 49 ключей), Shutterstock (описание до 150 в форме).
- **Исправления** `MetadataSanitizer`: `title_commas`, `title_too_long`, `description_too_long` (обрезка по слову), `keyword_duplicates` (в том числе единственное и множественное число: «daisy» и «daisies»; ограничение — изредка склеиваются разные слова вроде «glass» и «glasses»), `keywords_too_many`, `category_invalid`, `categories_too_many`.
- **Editorial:** модель только отмечает `looks_editorial` (видны бренды, узнаваемые люди, событие) — решает автор.

## Генерация для работ

`Services\Metadata\AssetMetadataService`: `generate()` платит за генерацию и сохраняет её в `asset_generations`, `apply()` пишет её в работу. `available()` — настроен ли провайдер (есть ключ): без ключа ничего не ставится в очередь.

### Источники полей

`assets.metadata_sources` — откуда пришло каждое поле (`App\Enums\MetadataSource`): `{"title": "file", "keywords": "ai", "description": "user"}`. Поля: `title`, `description`, `keywords`, `categories`.

| Источник | Когда ставится |
|---|---|
| `file` | При обработке загрузки найдено в файле (`Services\Assets\FileMetadataReader`) |
| `ai` | Записано из генерации |
| `user` | Пользователь изменил поле (`PATCH /api/assets/{ulid}` с этим полем) |

**Заполнение** (после загрузки и для выбранных работ) пишет поле, только если оно пустое и его источник не `user`. Категории — по маркетплейсам: добавляются только маркетплейсы, у которых категорий ещё нет. **Замена** (пользователь попросил: перегенерация или восстановление) пишет названные поля при любом источнике. Пустое сгенерированное значение поле никогда не очищает. Категории записываются только для подключённых маркетплейсов и из их текущих списков (генерация из истории могла быть сделана до отключения маркетплейса). Работа перечитывается под блокировкой: пользователь мог изменить её, пока модель отвечала.

### Метаданные из файла

`FileMetadataReader` при обработке загрузки (`ProcessAssetUpload`) читает начало файла (до 4 МБ):

- **XMP** (Lightroom, Bridge, Photoshop) из любого файла, где пакет лежит несжатым — JPEG, TIFF, PNG, EPS, SVG, MP4 с пакетом в начале: `dc:title`, `dc:description`, `dc:subject`. Главнее IPTC;
- **IPTC** из JPEG: Object Name (или Headline), Caption-Abstract, Keywords; Latin-1 переводится в UTF-8;
- **ИИ:** тип источника IPTC `trainedAlgorithmicMedia` / `compositeWithTrainedAlgorithmicMedia` (так его пишут и XMP, и манифест C2PA) ставит `is_ai_generated`. Модель этот флаг не угадывает.

Тексты обрезаются до 200 символов, ключевые слова — как при правке (нижний регистр, без повторов, до 50, каждое до 100 символов); список, записанный одной строкой через запятую или точку с запятой, разбивается.

### Когда генерируется

- **После загрузки** — `ProcessAssetUpload` после создания работы ставит `GenerateAssetMetadata` в очередь `metadata`, если у пользователя включено «Fill in metadata on upload» (`metadata.autofill_on_upload`, KB-36) и провайдер настроен. Задача ничего не платит, если пустых полей не осталось (например, всё пришло из файла).
- **По запросу** — API ниже.

`GenerateAssetMetadata`: до 3 ошибок провайдера (паузы 30 и 120 с) в пределах 3 часов (`retryUntil`); вторая задача для работы, которая уже генерируется, ждёт первую (откладывается на 30 с, попытки при этом не тратятся) — её могли попросить позже; работа в корзине не генерируется; исчерпанный лимит — запись в лог без повторов. Генерация не оплачивается, если записать нечего (`AssetMetadataService::needsFilling()`): все поля либо заполнены, либо принадлежат пользователю, а категории есть у всех включённых маркетплейсов со списками.

### Состояние «генерируется»

`AssetMetadataService::queue()` ставит `assets.metadata_generating_at` (в ответе `metadata_pending`) и задачу; `finish()` в конце задачи (не снимает отметку, поставленную заново после этой задачи) — при успехе, если записать нечего, при исчерпанном лимите и после окончательной ошибки (`failed()`) — снимает отметку и отправляет уведомление `EntityChanged` (`asset` / `metadata`). Пока провайдер падает и задача повторяется, отметка остаётся. Библиотека по уведомлению (или опросом без Pusher) запрашивает работу заново — `docs/realtime.md`.

### История и лимит

`asset_generations` — каждая оплаченная генерация: работа (`null` после удаления работы — генерация всё равно засчитана), `trigger` (`upload` / `manual`), модель, ответ целиком (`result`: title, description, keywords, categories, looks_editorial, fixes), токены, `cost_usd`, время. Восстановление из истории не платное.

Лимит — `METADATA_MONTHLY_LIMIT` (1000) генераций на пользователя за календарный месяц, автоматических и ручных вместе (`GenerationLimitReached`, 429). Лимит мягкий: проверка без блокировки, параллельные задачи могут превысить его на одну-две генерации.

### API

Все маршруты — `auth:api` + `verified`; чужая работа — 404; провайдер не настроен (нет ключа) — 503 для генерации и пакета.

| Метод | URL | Что делает |
|---|---|---|
| `GET` | `/api/assets/{ulid}/generations` | История работы, новые первыми (до 20); `meta.remaining` — сколько генераций осталось в этом месяце |
| `POST` | `/api/assets/{ulid}/generations` | Генерирует сейчас и заменяет поля `fields` (по умолчанию все четыре). Ответ 201: `data` — работа (`AssetResource`), `generation`, `meta.remaining`. Одна попытка с таймаутом 30 с (пользователь ждёт ответа; повторы — только у фоновой задачи). Сбой провайдера — 502 с сообщением, ничего не записано. Не больше 20 в минуту на пользователя |
| `POST` | `/api/assets/{ulid}/generations/{id}/apply` | Восстанавливает генерацию из истории этой работы в поля `fields`, без нового запроса к модели |
| `POST` | `/api/assets/generations` | `assets` — до 100 работ: ставит заполнение в очередь (только пустые поля), 202 с `data.queued`. Чужие работы пропускаются. Не хватает лимита на все — 429 |

Токены и стоимость в ответы не попадают, они только в `asset_generations`.

Интерфейс — метка «AI», счётчики, «Перегенерировать всё», «Вернуть сгенерированное» и заполнение выбранных работ — `docs/library.md`, «Автозаполнение в панели» и «Выбор нескольких работ».

## Настройки

| Переменная | По умолчанию | Что |
|---|---|---|
| `METADATA_DRIVER` | `openai` | Провайдер |
| `METADATA_IMAGE_SIZE` | `1024` | Длинная сторона картинки для модели |
| `OPENAI_API_KEY` | — | Ключ отдельного проекта `kadrobit` на platform.openai.com (расходы и лимиты отдельно от других проектов) |
| `OPENAI_METADATA_MODEL` | `gpt-6-luna` | Модель |
| `OPENAI_METADATA_REASONING_EFFORT` | `low` | Рассуждение; пусто — не передаётся. Токены рассуждения оплачиваются как выход |
| `OPENAI_METADATA_IMAGE_DETAIL` | `auto` | `low` / `high` / `auto` |
| `OPENAI_METADATA_MAX_OUTPUT_TOKENS` | `4000` | Потолок вывода вместе с рассуждением |
| `OPENAI_METADATA_TIMEOUT` | `40` | Секунды на одну попытку; три попытки с паузами укладываются в `--timeout=150` обработчика `metadata` |
| `OPENAI_METADATA_RETRY_DELAY_MS` | `2000` | Пауза перед повтором после 429 или 5xx, умножается на номер попытки |

## Сравнение моделей

```bash
php artisan metadata:evaluate                                   # последние 20 работ, модели из metadata.evaluation_models
php artisan metadata:evaluate --model=gpt-6-luna --model=gpt-6.1-sol --limit=50
php artisan metadata:evaluate --asset=<ulid> --asset=<ulid>
php artisan metadata:evaluate --dir=~/Pictures/stock-sample      # картинки из папки, без загрузки в библиотеку
php artisan metadata:evaluate --effort= --detail=low            # без рассуждения, картинка в низком качестве
```

Команда ничего не сохраняет в работы. Всем моделям уходят одни и те же картинки и списки категорий всех маркетплейсов. Итог в консоли: успешные ответы, средние токены, сколько ответов пришлось исправлять, $ за 1000 картинок по фактическим токенам, время. Отчёт — `storage/app/private/metadata-evaluations/<дата>/`: `results.json` (`samples` — список картинок с ответами моделей, `skipped` — картинки, которые не удалось прочитать) и `report.html` (картинка и ответы моделей рядом, первые 10 ключевых слов выделены). Нечитаемая картинка (битый файл, превью нет на диске) пропускается с предупреждением, остальные сравниваются.

### Результаты 25.10.2026

6 фото из библиотеки (цветы, пейзажи, город, море), картинка 1024 px, рассуждение `low`, списки категорий Adobe Stock и Shutterstock. Второй прогон, после уточнения промпта.

| Модель | $ / 1000 картинок | Вход / выход (рассуждение), токены | Время | Исправлено ответов | Качество |
|---|---|---|---|---|---|
| **gpt-6-luna** | **0.40** | 1 764 / 439 (155) | 5.5 с | 0 из 6 | Точные заголовки, описания дополняют заголовок, правила соблюдает. Слабее Sol в деталях (не заметил море на фото с домом) |
| gpt-5.6-luna | 0.77 | 1 764 / 346 (123) | 5.0 с | 1 из 6 | Хорошее распознавание, но выбрасывает запятые из описаний вопреки промпту, ключевые слова длиннее и повторяют друг друга |
| gpt-5.4-mini | 2.47 | 1 764 / 254 (44) | 2.2 с | 2 из 6 | Самая быстрая. Описания короткие и без запятых, противоречивые ключевые слова (sunrise, daybreak у заката), спорные категории (Backgrounds/Textures) |
| gpt-6.1-sol | 7.24 | 1 764 / 371 (28) | 7.9 с | 0 из 6 | Лучшая точность: мелкие детали («crepuscular ray», лента на шляпе, набережная), лучшие описания. В 18 раз дороже Luna |

Первый прогон (до уточнения промпта) показал то же соотношение цен; `gpt-6-luna` давал пары «daisy / daisies» — теперь это запрещено в промпте и убирается `MetadataSanitizer`.

**Выбор: `gpt-6-luna`** — качество близко к `gpt-6.1-sol`, правила соблюдает лучше других, около $0.0004 за генерацию: 5 000 работ в месяц — около $2. `gpt-6.1-sol` — кандидат для отдельной «точной» перегенерации, если понадобится.

Ограничения выборки: 6 фото одного автора, нет векторов, иллюстраций и кадров видео. Повторить на 50–100 разных работах (`--dir` или `--limit`), когда в библиотеке появятся векторы, иллюстрации и видео.
