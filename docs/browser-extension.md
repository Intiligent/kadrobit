# KB-54 - Marketplaces: расширение Chrome для работы с кабинетами стоков

Задача: [KB-54](https://github.com/Intiligent/kadrobit/issues/54).

## Цель

Одно расширение Chrome для всех стоков: оно связывает браузер автора с его аккаунтом Kadrobit и делает на сайте стока то, что нельзя сделать с сервера. У стоков нет публичного API, вход закрыт капчей или защитой от ботов, и Submit возможен только в их интерфейсе. Автор уже проверил и одобрил работы в Kadrobit, поэтому повторное подтверждение на сайте стока — лишний шаг.

Расширение работает только в уже открытой сессии автора: пароли стоков оно не видит и не хранит, капчу не обходит.

Эта задача описывает общие требования и каркас. Особенности каждого стока — в подзадачах, по порядку:

- [ ] [KB-79](https://github.com/Intiligent/kadrobit/issues/79) Основа расширения и API Kadrobit для него
- [ ] [KB-84](https://github.com/Intiligent/kadrobit/issues/84) Shutterstock — категории, метаданные и отправка на модерацию
- [ ] [KB-80](https://github.com/Intiligent/kadrobit/issues/80) 123RF — Proceed и отправка на проверку
- [ ] [KB-81](https://github.com/Intiligent/kadrobit/issues/81) Adobe Stock — CSV, загрузка и отправка на проверку

## Подключение к Kadrobit

- Авторизация через Laravel Passport: OAuth 2 Authorization Code с PKCE, публичный клиент без секрета.
- Расширение открывает окно авторизации Kadrobit через `chrome.identity.launchWebAuthFlow`. Автор, уже вошедший на сайт, нажимает «Разрешить», и расширение получает access-токен со скоупами и refresh-токен.
- Запасной способ — персональный токен: его выпускают в настройках Kadrobit и вставляют в расширение вручную.
- Токен расширения даёт доступ только к API расширения, ни к чему больше.
- В Kadrobit виден список подключённых расширений, любое можно отозвать; после отзыва расширение отключается сразу.
- Кнопка «Выйти» в расширении отзывает токен и позволяет войти под другим аккаунтом.

## Базовые функции

У каждого стока своя механика: как найти файлы Kadrobit, что сделать до отправки (у 123RF — Proceed, у Adobe без SFTP — загрузить файлы через портал), как отправить и как узнать статус модерации. Общее — каркас адаптера и то, что адаптер сообщает в Kadrobit. Механика каждого стока описывается в его подзадаче.

### 1. Обнаружение загруженных файлов

- [ ] На сайте стока расширение находит файлы, загруженные Kadrobit, и сообщает платформе, что они дошли и обработались. Это нужно для статуса или прогресса публикации в Kadrobit.
- [ ] Файл на стоке сопоставляется с публикацией по имени файла, которое Kadrobit задаёт при загрузке, а где имени мало — ещё по размеру или дате.
- [ ] Внутренний ID работы на стоке передаётся в Kadrobit и сохраняется в `external_id` публикации, ссылка на работу — в `external_url`. По этому ID потом сопоставляются статусы модерации, продажи и любые действия с работой.

### 2. Отправка на модерацию

- [ ] Настройка «Автоматическая отправка» у каждого подключённого стока отдельно, по умолчанию включена.
- [ ] Если настройка включена, расширение само отправляет обнаруженные работы на модерацию. Перед отправкой оно проверяет описание, ключевые слова, категории и прочие поля стока и при необходимости заполняет их данными из Kadrobit. Включая настройку, автор соглашается и с действиями, которые на сайте стока означают принятие условий (Proceed на 123RF); это сказано в подсказке к настройке.
- [ ] Если настройка выключена, расширение только обнаруживает файлы, а Submit автор делает на сайте сам.
- [ ] Главный источник метаданных — Kadrobit: правки автора на сайте стока перезаписываются при следующем заполнении.
- [ ] После записи метаданных публикация в Kadrobit отмечается как обновлённая: пометка «изменено после отправки» снимается.
- [ ] Для каждого стока проверить правила: где автоматизация кабинета запрещена, есть риск блокировки аккаунта. Результат записать в `docs/marketplaces/`.

### 3. Статусы модерации

- [ ] Адаптер опрашивает статусы работ на стоке (на модерации, принята, отклонена) и передаёт их в Kadrobit со временем сверки.
- [ ] Статусы обновляются, только когда у автора открыт сайт стока, поэтому Kadrobit и попап показывают, когда была последняя сверка.

### 4. Надёжность

- [ ] Ответы внутреннего API стока проверяются по форме: если сток его поменял, расширение показывает понятную ошибку и ничего не отправляет, а не ломается молча.

## Интерфейс

Панель на сайт стока не встраиваем: всё показывается в попапе расширения, в три блока. Списка работ в попапе нет, только статистика.

1. **Аккаунт** — есть всегда: аккаунт Kadrobit и кнопка «Выйти».
2. **Общая статистика** по платформе: загружено, на модерации, отклонено.
3. **Текущий сток** — только когда открыт сайт стока: статистика по нему, время последней сверки и последнее действие расширения (например, «найдено 12 файлов, отправлено 10, ошибок 2»). На других сайтах блока нет.

Тексты расширения — только на английском, без переводов.

## Расширение

- Manifest V3. Права только на домены стоков из подзадач и домен Kadrobit.
- Сборка и версия — «Как устроено расширение», «Сборка».
- Публикация в Chrome Web Store. Расширение, которое действует в чужих кабинетах, может не пройти проверку магазина; запасной путь — распакованное расширение или установка по ссылке.

## Как устроено в Kadrobit

Этап [KB-79](https://github.com/Intiligent/kadrobit/issues/79).

### Вход расширения

- **Клиент OAuth** — публичный (без секрета), Authorization Code с PKCE, ID задан в `config/extension.php` (`client_id`), его создаёт `OauthSeeder`. Redirect URI — `https://<extension-id>.chromiumapp.org/`.
- **ID расширения** — `fpdfkhaaacgkafhamlleoadkbkekeokp`, выводится из публичного ключа в `extension/manifest.json` (`key`). Закрытый ключ — `storage/extension.key`, в git его нет: он нужен, только чтобы сохранить тот же ID при публикации в Chrome Web Store. Ключ хранится у владельца в секретах.
- **Страница согласия** — `GET /oauth/authorize` (маршрут Passport) рисует Inertia-страницу `auth/authorize` (`AppServiceProvider::authorizationPage()`). «Разрешить» и «Отмена» — обычные формы на `POST`/`DELETE /oauth/authorize`, Passport отвечает редиректом в расширение. Если у пользователя уже есть живой токен этого клиента с теми же скоупами, Passport пропускает согласие.
- **Скоуп `extension`.** Токены расширения пускает только группа `api/extension/*` (`scopes:extension`). Остальное API их не пускает (`not-extension`, `RejectExtensionTokens`, ответ 403), а токен веб-сессии без скоупа не пускает API расширения. Токеном расширения считается и любой токен его OAuth-клиента, даже выпущенный без скоупа: такой не пустит ни одно API.
- **Срок жизни.** Access-токен живёт как сессия (`SESSION_LIFETIME`), refresh-токен — 30 дней (`Passport::refreshTokensExpireIn`, касается только OAuth-клиентов: веб-сессия работает на персональных токенах). Расширение продлевает токен само; не пользовались месяц — вход заново, одним нажатием «Разрешить».
- **Персональный токен** (запасной вход) выпускается в Settings → Extension со скоупом `extension` и живёт `EXTENSION_TOKEN_DAYS` дней (365). Passport задаёт один срок всем персональным токенам и читает его при каждом выпуске, поэтому `ExtensionTokens::issue()` меняет его на время выпуска одного токена и возвращает обратно. Токены веб-сессии это не затрагивает.
- **Подключённые расширения** — живые токены со скоупом `extension` или клиента расширения (`ExtensionTokens::connections()`): у OAuth-подключения один токен, при обновлении он заменяется. Отключение отзывает токен и его refresh-токен.
- **Сброс пароля** отзывает все токены расширения (`PasswordResetListener`): тот, кто знал старый пароль, мог подключить своё расширение на год. После сброса расширение входит заново.

### API расширения

| Метод | URL | Что делает |
|---|---|---|
| `GET` | `/api/extension/me` | Аккаунт Kadrobit, общие счётчики и аккаунты стоков, которые поддерживает расширение: `auto_submit` и счётчики по каждому |
| `GET` | `/api/extension/listings?marketplace=<code>` | Работы на сервере стока (`status = sent`) по всем аккаунтам пользователя на этом стоке, страницами по 200 (cursor). Имя файла, ID и ссылка, статус модерации, текущие метаданные с названиями категорий, `outdated` и `metadata_hash` |
| `POST` | `/api/extension/listings/report` | Что расширение нашло на сайте, до 500 работ за раз: `external_id`, `external_url`, `moderation_status` (время сверки ставится само), `metadata_hash` — метаданные записаны на сток |
| `POST` | `/api/extension/logout` | «Выйти»: отзывает токен запроса и его refresh-токен |

- **Счётчики** (`ExtensionStats`): `sent` — работ на серверах стоков, `pending`, `accepted`, `rejected` — по последней сверке, `checked_at` — время последней сверки. Считаются только по аккаунтам из списка `accounts`, поэтому общий счётчик — их сумма.
- **Выключенные аккаунты** (`status = disabled`) расширение не видит: `listings` их работ не отдаёт, `report` их не меняет.
- **Метаданные.** `metadata_hash` — хеш метаданных, которые расширение получило в `listings`. Если работу за это время изменили, хеш не совпадёт, и публикация останется «изменено после отправки». Если совпал, в `metadata` публикации записываются текущие метаданные.
- Чужие работы и работы, ещё не дошедшие до стока, `report` пропускает молча и не считает в `updated`.
- Поле, которого расширение на сайте не нашло, в `report` не передаётся; `null` — ошибка 422, поэтому сохранённое значение не затирается.

### Данные

- `asset_listings`: `external_url` после `external_id`, `moderation_status` (`App\Enums\ModerationStatus`: `pending`, `accepted`, `rejected`, null — неизвестно) после `status`, `moderation_checked_at` после `sent_at`. Таблица пересобрана миграцией `2026_11_01_000001_add_moderation_to_asset_listings_table.php`.
- **Автоматическая отправка** — `marketplace_accounts.settings.auto_submit`, по умолчанию включена (`MarketplaceAccount::autoSubmits()`). Меняется через `PATCH /api/marketplace-accounts/{id}` (`auto_submit`), только у стоков из `config/extension.php` (`marketplaces`), у остальных — 422. В Settings → Marketplaces это флажок под названием аккаунта.

### Settings → Extension

`/settings/extension` (`SettingsController@extension`): архив последней версии из `public/extension/release.json`, инструкция по установке и обновлению, подключённые расширения с кнопкой «Отключить», выпуск персонального токена (`POST /api/extension-tokens`, токен показывается один раз), отключение — `DELETE /api/extension-tokens/{id}`.

## Как устроено расширение

Папка `extension/` в корне репозитория. Manifest V3, тексты только на английском.

| Файл | Что делает |
|---|---|
| `manifest.json` | Манифест; `version` — версия расширения, `key` закрепляет ID. `@kadrobit` и `@marketplaces` сборка заменяет адресом Kadrobit и сайтами стоков |
| `src/marketplaces.js` | Стоки расширения (как `config/extension.php`): код, название, адреса сайтов |
| `src/background/` | Фоновый воркер — единственный, кто хранит токен и ходит в Kadrobit: вход (`auth.js`), API (`kadrobit.js`), последнее действие на каждом стоке (`actions.js`), сообщения (`index.js`) |
| `src/content/` | Скрипт на сайтах стоков: запускает адаптер стока при открытии страницы и затем раз в 5 минут, пока вкладка открыта и видна (стоки показывают новые файлы через несколько минут), и сразу по «Check now» из попапа (`runner.js`). Пока идёт проход по стоку, второй (из другой вкладки) не начинается: фоновый воркер отвечает `busy` |
| `src/adapters/` | Список адаптеров и их интерфейс (`index.js`); Shutterstock — `shutterstock.js` ([`marketplaces/shutterstock`](marketplaces/shutterstock/README.md)), 123RF и Adobe Stock — KB-80, KB-81 |
| `src/core/` | PKCE, проверка формы ответов сайта стока (`shape.js`), сообщения между частями расширения |
| `src/popup/` | Попап на Vue и Element Plus (тема та же, что у Kadrobit) |
| `public/icons/` | Иконки из знака логотипа (`icon.svg`, PNG собраны `rsvg-convert`) |

- **Вход.** «Sign in to Kadrobit» открывает `chrome.identity.launchWebAuthFlow` на `/oauth/authorize` с PKCE (S256) и `state`; код меняется на токены в `/oauth/token`. Токены лежат в `chrome.storage.local`. Access-токен обновляется за минуту до истечения, раз в 12 часов — фоном (`chrome.alarms`), чтобы не истёк refresh-токен. Отклонённое обновление или 401/403 от API — выход с сообщением «войдите снова». Запасной путь — «Use a personal token instead»: токен сохраняется, только если Kadrobit его принял, и не обновляется (401 — сразу выход). Если Kadrobit недоступен, расширение остаётся подключённым, попап показывает причину, «Try again» и «Sign out».
- **Проход адаптера** (`content/runner.js`): автор вошёл на сток → работы стока из Kadrobit и аккаунты с их `auto_submit` → `adapter.sync()` → `report` в Kadrobit → запись действия для попапа. Ошибка любого шага, в том числе изменившийся API сайта (`ShapeError`), записывается как действие и показывается в попапе.
- **Адаптер** знает только свой сайт: находит работы по `remote_filename`, заполняет поля, отправляет на проверку те, что разрешает `shouldSubmit()` (автоотправка аккаунта), читает статус проверки и отвечает отчётом по каждой работе. Ответы внутреннего API сайта проверяет `expectShape()`.

### Сборка

```sh
npm run build                                                   # приложение и расширение
npm run build:extension                                         # только расширение, для APP_URL из .env
EXTENSION_APP_URL=https://kadrobit.loc npm run build:extension  # для локального Kadrobit
```

`extension/build.js` собирает попап и фоновый воркер (ES-модули) и отдельно скрипт стоков (один файл: Chrome не грузит модули в content scripts) в `extension/dist`, пишет манифест, упаковывает `public/extension/kadrobit-extension-<версия>.zip` и `release.json` для Settings → Extension. Обе папки в `.gitignore`. Без `APP_URL` (и `EXTENSION_APP_URL`) расширение не собирается — с предупреждением, сборка приложения при этом не падает. Код не минифицируется: так его проще проверять. Новая версия — поднять `version` в `manifest.json`.

Для разработки: `chrome://extensions` → Developer mode → Load unpacked → `extension/dist`; после пересборки — кнопка перезагрузки расширения. ID у распакованного расширения тот же, что у собранного, благодаря `key`.

Тесты — `tests/js/extension` (`npm test`).

## Планы (не входит в эту задачу)

- Импорт портфолио: новый автор с работами на стоках и пустым Kadrobit. Расширение проходит по работам автора на стоке и передаёт в Kadrobit их ID, метаданные, статусы и превью. Механизм — отдельно под каждый сток.

## Критерии приёмки

- Расширение подключается к Kadrobit через OAuth с PKCE и через персональный токен; выход отзывает токен; подключение видно в Kadrobit и отзывается оттуда.
- На каждом из стоков в подзадачах работа, отправленная из Kadrobit, доходит до модерации без ручного заполнения полей, если для стока включена автоматическая отправка.
- При выключенной настройке ничего не отправляется.
- В Kadrobit видны ID работы на стоке, ссылка на неё, статус модерации и время сверки.
- Попап показывает три блока, блок стока — только на сайте стока.
- В настройках Kadrobit можно скачать последнюю версию расширения и по инструкции установить его.
- `docs/marketplaces/README.md` обновлён.

## Шаги для владельца

- [ ] Аккаунт разработчика в Chrome Web Store (разовый взнос).
- [ ] Закрепить ID расширения (`key` в манифесте), чтобы redirect URI не менялся.
